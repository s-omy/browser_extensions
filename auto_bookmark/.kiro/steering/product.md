# Product Overview

ブラウザのブックマークを、AI が「最適なフォルダ」へ自動で振り分ける Chrome 拡張機能（Manifest V3）。
サーバーを持たず、利用者自身の API キーでプロバイダ（既定は Gemini、任意で LiteLLM Proxy 等の OpenAI 互換エンドポイント）を直接呼び出す。個人開発の拡張機能で、主な想定利用者は「ブックマークが増えすぎて整理できない個人」と、自前の LLM 環境を持つ開発者。

## Core Capabilities

- **自動振り分け保存**: 開いているページを、右クリック／ツールバーアイコン／ショートカットから、AI が選んだフォルダへ保存する。判定できなければ推測せず「未分類」へ入れ、理由を通知する。
- **クイック保存・取り消し**: AI を使わず指定フォルダへ保存する経路と、保存直後の「元に戻す」を常に用意する。
- **既存ブックマークの整理（設定画面）**: ① フォルダ解析（各フォルダの説明文を生成）→ ② 再カテゴライズ（差分プレビューを見て適用、直前の1回分は取り消せる）→ ③ ナレッジ同期（URL とタイトルからの推定を蓄積）。
- **プロバイダの切り替え**: Gemini と OpenAI 互換エンドポイントを、設定画面で切り替えられる。
- **プライバシー制御**: 保護フォルダ、送信しない URL（ドメイン除外・クエリ除去・http/https 以外は常に除外）、動作ログ。

## Target Use Cases

1. 閲覧中のページを、考えずにワンアクションで適切な場所に保存したい。
2. 長年の蓄積で散らかったブックマークを、内容を確認しながら一括整理したい。
3. データを Google に送りたくない／自前の LLM で動かしたい（自前ホストの LiteLLM + Ollama 等）。

## Value Proposition

- **データの行き先が利用者の管理下**: 中継サーバーがなく、送信先は利用者が設定したプロバイダだけ。送る範囲は利用者が絞れる。
- **AI を信用しすぎない設計**: 判定は候補フォルダの ID に拘束し、確信度が低い・失敗した場合は安全側（未分類・現状維持）に倒す。
- **費用と変更が予見できる**: 課金が発生する操作は実行前に件数と呼び出し回数を提示し、移動は差分プレビューで確認・取り消しできる。

## Product Principles（判断の拠り所）

1. **失敗を成功に見せない**: 判定できなかったものを「うまくいった」ように表示しない。理由を示す。
2. **推測で動かさない**: 迷ったら移動しない／未分類にする。ユーザーの既存の整理を壊さない。
3. **ユーザーが持ち込んだ構造を尊重する**: `[名前]` で囲んだ保護フォルダ（配下含む）は、移動・送信の対象にしない。
4. **課金・送信は明示的に**: 自動で全件処理しない。実行は手動で、事前確認を挟む。
